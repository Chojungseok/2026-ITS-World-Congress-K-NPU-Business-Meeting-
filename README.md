# K-NPU Connect

강릉 K-NPU 전환 밋업의 ITS 기업 ↔ NPU 기업 1:1 비즈매칭 프론트엔드 프로토타입입니다.

## 현재 단계

초기 저장소는 커밋과 소스 파일 없이 `.git`만 존재했습니다. 별도 빌드나 외부 라이브러리가 필요 없는 HTML / CSS / JavaScript ES 모듈 구조로 구현했습니다. GitHub Pages의 저장소 하위 경로에서도 사용할 수 있도록 상대 경로와 해시 라우팅을 사용합니다.

Google Apps Script, Google Sheets, 운영 인증, 실제 메일 발송은 아직 연결하지 않았습니다. GitHub Pages에는 로컬 모의 데이터 기반 프로토타입을 배포합니다.

## 로컬 실행

Node.js 20 이상을 권장합니다. 패키지 설치는 필요 없습니다.

```powershell
npm start
```

브라우저에서 `http://127.0.0.1:4173`에 접속하세요. 종료는 터미널에서 Ctrl+C입니다. 포트 충돌 시 PowerShell에서 `$env:PORT = '4174'`를 지정한 뒤 실행할 수 있습니다.

ES 모듈을 사용하므로 HTML 파일을 직접 더블클릭하지 말고 HTTP 서버로 실행하세요.

```powershell
npm test
```

## 구현된 화면

| 경로 | 기능 |
| --- | --- |
| `#apply` | ITS 기업 정보, NPU·시간 선택, 참석인원·상담내용, 신청ID 발급 |
| `#lookup` | 신청ID+이메일 조회, 승인대기·매칭확정 신청 취소 |
| `#npu` | 기업 선택 데모 입장, 기업별 목록·필터·상세, 승인·거절, 시간별 정원 |
| `#admin` | 전체·대기·확정·거절 건수, 취소 건수, 시간별 NPU 현황, 네 가지 복합 필터 |

신청 상태는 **승인대기 → 매칭확정 또는 매칭거절**로 전환됩니다. 승인대기·매칭확정 상태에서는 신청취소가 가능합니다. 거절·취소한 신청은 다시 승인할 수 없습니다.

정원은 동일 NPU·동일 시간의 **매칭확정 건수**입니다. 딥엑스 5건, 모빌린트 2건, 퓨리오사 1건, 리벨리온 2건이며, 참석인원과 별개입니다. 대기 건수는 정원을 차지하지 않습니다. 이미 정원이 찬 시간에는 신규 신청도 막습니다.

현재 예시 시간표는 13:00~16:00, 30분 단위 6개 슬롯입니다. 실제 행사 일시가 지정되지 않아 임의의 개최 날짜는 표시하지 않습니다. 참석인원 입력 범위 1~20명은 데모 설정이며 운영 시 확정해야 합니다.

## 데모 확인 흐름

1. 예시 정보로 상담 신청을 작성합니다.
2. 완료 화면에서 신청ID를 복사하거나 ‘신청 확인하기’를 누릅니다.
3. NPU 승인 관리에서 신청한 NPU 기업을 선택하고 데모 화면에 입장합니다.
4. 승인 또는 거절 후 신청 확인 화면에서 결과를 조회합니다.
5. 운영 대시보드에서 신청 목록과 시간별 확정 건수를 확인합니다.
6. 확정 신청을 취소하면 해당 시간의 정원이 다시 열립니다.

기본 조회 예시는 `DEMO-0001` / `demo1@example.com`입니다. 예시 13건을 제공합니다. 퓨리오사의 13:00 대기 건은 이미 확정 정원이 찬 상태이므로 승인 시 정원 초과가 차단됩니다.

왼쪽 메뉴의 ‘데모 데이터 초기화’는 확인 창을 거쳐 이 브라우저의 변경 사항을 지우고 예시 데이터를 복구합니다.

## 저장 및 인증 범위

- 데이터는 같은 브라우저·같은 origin의 localStorage에 저장됩니다. 새로고침 후 유지되지만 다른 기기나 브라우저와 공유되지 않습니다.
- 실제 개인정보를 입력하지 마세요. localStorage는 인증이나 안전한 개인정보 저장소가 아닙니다.
- NPU·관리자 인증은 구현 전입니다. 데모 입장은 누구나 가능하며 접근 제어의 보안 경계를 제공하지 않습니다.
- 프론트엔드에는 실제 승인코드, Google 인증정보, Sheets ID가 없습니다.
- 모의 API도 기업별 조회·상태 변경 범위를 검사하며, Web Locks 지원 브라우저에서는 같은 origin의 여러 탭 변경을 직렬화합니다. Web Locks 미지원 환경에서는 단일 탭 처리만 직렬화됩니다.
- 실제 다중 사용자 정원 보호는 GAS 서버에서 반드시 다시 구현해야 합니다. 운영 준비가 완료된 서비스가 아닙니다.

## 후속 연결 및 GitHub Pages

[Google Apps Script 연결 설계](docs/google-apps-script-integration.md)에 데이터 매핑, API 계약, 인증·원자적 정원 검증과 후속 확인 항목을 정리했습니다.

현재 파일은 GitHub Pages 루트 정적 배포 구조에 맞춰 작성되어 있습니다. 공개 저장소에 게시할 때는 데모 데이터 외의 개인정보·인증정보가 포함되지 않도록 하고, 저장소의 Pages 설정에서 배포 브랜치의 루트 폴더를 지정합니다. 배포 대상은 Chojungseok/2026-ITS-World-Congress-K-NPU-Business-Meeting- 저장소입니다. Settings > Pages에서 Deploy from a branch, main, /(root)를 선택하고 저장하면 됩니다. Pages 활성화 전에는 사이트 URL이 열리지 않습니다.


## 검증 결과

- Node 단위 테스트 11개 통과: 기업별 정원, 중복 신청, 소유 범위, 상태 전이, 취소 후 정원 반환, 손상 데이터, 입력 검증.
- Microsoft Edge 헤드리스: 신청 → 승인 → 신청 조회 → 취소, 거절, 정원 초과 승인 차단, 관리자 복합 필터 확인.
- 320 / 390 / 768 / 1024 / 1440px에서 네 화면의 페이지 가로 넘침 없음, 모바일 메뉴 동작 확인.
- 동일 브라우저 두 탭의 마지막 자리 동시 승인에서 한 건만 확정됨을 확인.
- 브라우저 오류 0건. 실제 GAS 서버 동시성·권한 검증은 아직 수행 대상이 아닙니다.

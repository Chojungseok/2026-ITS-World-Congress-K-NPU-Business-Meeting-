# K-NPU Connect

강릉 K-NPU 전환 밋업의 ITS 기업 ↔ NPU 기업 1:1 비즈매칭 프론트엔드 프로토타입입니다.

## 현재 단계

초기 저장소는 커밋과 소스 파일 없이 `.git`만 존재했습니다. 별도 빌드나 외부 라이브러리가 필요 없는 HTML / CSS / JavaScript ES 모듈 구조로 구현했습니다. GitHub Pages의 저장소 하위 경로에서도 사용할 수 있도록 상대 경로와 해시 라우팅을 사용합니다.

Google Apps Script, Google Sheets, 운영 인증, 실제 메일 발송은 아직 연결하지 않았습니다. 현재는 로컬에서 확인한 프론트엔드 프로토타입을 GitHub에 공유하는 단계입니다. GitHub Pages 활성화와 GAS/Sheets 연결은 별도 단계입니다.

## 로컬 실행

Node.js 20 이상을 권장합니다. 패키지 설치는 필요 없습니다.

Windows에서는 **start-local.cmd 파일을 더블클릭**하세요. 서버가 준비되면 기본 브라우저가 자동으로 열립니다. 사용 중에는 실행 창을 열어 두고, 끝나면 Ctrl+C 또는 창 닫기로 종료합니다. 이미 이 폴더의 서버가 실행 중이면 기존 화면을 다시 엽니다.

터미널에서 실행하려면 다음 명령을 사용합니다.

```powershell
npm start
```

브라우저에서 `http://127.0.0.1:4173`에 접속하세요. 종료는 터미널에서 Ctrl+C입니다. 포트 충돌 시 PowerShell에서 `$env:PORT = '4174'`를 지정한 뒤 실행할 수 있습니다.

index.html을 직접 열면 실행 안내가 표시됩니다. 실제 앱은 HTTP 서버로 열어야 합니다. 브라우저 보안 설정을 변경할 필요는 없습니다.

```powershell
npm test
```

## 구현된 화면

| 경로 | 기능 |
| --- | --- |
| `#apply` | ITS 기업 정보, NPU·시간 선택, 참석인원·상담내용, 신청ID 발급 |
| `#lookup` | 신청ID 단독 조회, 승인대기·매칭확정 신청 취소 |
| `#npu` | 기업 선택·로컬 승인코드 확인, 기업별 목록·필터·상세, 승인·거절, 시간별 정원 |
| `#matching` | 로그인한 NPU 기업의 시간별 확정 상담, 상담 카드 클릭으로 상세 조회 |
| `#admin` | 전체·대기·확정·거절 건수, 취소 건수, 시간별 NPU 현황, 네 가지 복합 필터 |

신청 상태는 **승인대기 → 매칭확정 또는 매칭거절**로 전환됩니다. 승인대기·매칭확정 상태에서는 신청취소가 가능합니다. 거절·취소한 신청은 다시 승인할 수 없습니다.

정원은 동일 NPU·동일 시간의 **매칭확정 건수**입니다. 초기값은 딥엑스 5건, 모빌린트 2건, 퓨리오사 1건, 리벨리온 2건이며, NPU 기업이 로그인 후 정원을 변경할 수 있습니다. 참석인원과 별개입니다. 대기 건수는 정원을 차지하지 않습니다. 이미 정원이 찬 시간에는 신규 신청도 막습니다.

상담 시간표는 16:50~17:30, 10분 단위 4개 슬롯입니다. 실제 행사 일시가 지정되지 않아 임의의 개최 날짜는 표시하지 않습니다. 참석인원 입력 범위 1~20명은 데모 설정이며 운영 시 확정해야 합니다.

## 데모 확인 흐름

1. 예시 정보로 상담 신청을 작성합니다.
2. 완료 화면에서 신청ID를 복사하거나 ‘신청 확인하기’를 누릅니다.
3. NPU 승인 관리에서 신청한 NPU 기업을 선택하고 아래 로컬 확인용 승인코드로 입장합니다.
4. 승인 또는 거절 후 신청 확인 화면에서 결과를 조회합니다.
5. NPU 메뉴의 매칭 현황에서 시간표를 확인하고 확정된 상담 카드를 눌러 상세 내용을 확인합니다.
6. 확정 신청을 취소하면 해당 시간의 정원이 다시 열립니다.

기본 조회 예시는 `DEMO-0001`입니다. 예시 13건을 제공합니다. 퓨리오사의 16:50 대기 건은 이미 확정 정원이 찬 상태이므로 승인 시 정원 초과가 차단됩니다.

왼쪽 메뉴의 ‘데모 데이터 초기화’는 확인 창을 거쳐 이 브라우저의 변경 사항을 지우고 예시 데이터를 복구합니다.

## NPU 기업 로컬 승인코드

| 기업 | 로컬 확인용 승인코드 |
| --- | --- |
| 딥엑스 (DEEPX) | `deepx20261022` |
| 모빌린트 (MOBILINT) | `mobilint20261022` |
| 퓨리오사 (FURIOSA) | `furiosa20261022` |
| 리벨리온 (REBELLIONS) | `rebellions20261022` |

선택한 기업과 코드가 일치해야 해당 기업의 신청 목록을 엽니다. 영문은 소문자이며, 앞뒤 공백은 무시합니다. 코드와 세션 토큰은 브라우저 저장소에 보관하지 않고 새로고침 시 다시 입력합니다.

이 코드는 로컬 시연용으로 공개된 값입니다. 운영용 보안 인증을 제공하지 않으며, GAS 연결 시 실제 승인코드의 저장·검증을 서버로 옮기고 새 운영 코드를 부여해야 합니다.

## NPU 매칭 현황

- NPU 화면에서는 운영 대시보드 메뉴 대신 매칭 현황을 제공합니다.
- 매칭 현황은 로그인한 기업의 매칭확정 상담만 시간대별로 표시합니다. 대기·거절·취소 신청은 NPU 승인 관리에서 확인합니다.
- 16:50~17:30의 4개 시간대에 기업명, 참석인원, 상담내용 요약과 확정 건수/정원을 표시합니다. 이전 시간표의 확정 신청도 별도 행으로 보존합니다.
- 상담 카드를 누르면 담당자·연락처·이메일·전체 상담내용을 확인할 수 있습니다.
- 기업 변경 버튼은 제거했고, 우측 상단은 로그인한 기업명으로 표시합니다. 모바일에서도 기업명을 표시합니다.

## 정원 변경 및 관리자 화면

- NPU 승인 관리와 매칭 현황에서 **최대 상담 건수 조절**을 제공합니다. 각 시간대에 0~50건의 정수를 입력하고 개별 저장합니다. 0건은 해당 시간의 접수·승인 중단이며 다른 시간대에는 영향을 주지 않습니다.
- 해당 시간대에 이미 확정된 상담 수보다 작게 정원을 줄일 수 없습니다. 변경과 승인은 같은 잠금 안에서 검증합니다.
- 정원은 localStorage에 저장되며 ITS 신청 시간 선택, NPU 시간표, 관리자 잔여 자리 표에 반영됩니다. 같은 브라우저의 다른 탭도 갱신됩니다.
- 첫 화면 하단 **관리자로 로그인**에서 관리자 화면에 입장합니다. 로컬 ID는 `ITSKOREA9911`, 비밀번호는 `ITSKOREA9911!`입니다. 로그인 없이 관리자 URL을 열면 로그인 화면이 표시됩니다.
- 관리자 **진행 현황**은 시간 × NPU 기업 표로 잔여 건수, 확정 건수/정원, 마감 또는 접수 중단, 기업별 총 남은 자리를 표시합니다.
- **전체 활동 로그** 하나로 신청·취소·NPU 승인·거절·시간별 정원 변경을 보여 줍니다. 처리 시각, 처리자, 신청ID, 기업, 담당자·인원, 상담 시간, 변경 전후 값을 확인하고 신청ID를 눌러 현재 신청 상세를 열 수 있습니다. 기본 최신순이며 오래된 순으로 전환할 수 있습니다. 신청ID·기업·담당자·시간·처리 유형 검색을 지원합니다.
- 진행 현황의 **잔여 건수 버튼**은 해당 NPU·시간의 상담 기업 팝업을 엽니다. 확정·대기를 구분하고 거절·취소도 펼쳐 확인할 수 있습니다. 기업별 상세와 목록 돌아가기를 제공하며, 열려 있는 팝업도 변경된 데이터로 갱신합니다.
- 관리자 화면에서는 NPU 승인 관리 메뉴를 숨깁니다.
- 이전 저장 데이터와 기본 예시는 ‘기존 상태’로 이관하며, 기록하지 않았던 과거 처리 시각이나 승인·취소 순서를 만들어내지 않습니다. 처리 시각이 없는 기록은 정렬 방향과 무관하게 로그 끝에 표시합니다. 기존 기업 단위 정원은 처음 한 번 각 시간대의 초기값으로 복사한 뒤 개별 관리합니다.
- 관리자 자격 증명 역시 로컬 확인용입니다. 실제 운영 전에는 NPU 인증과 함께 서버 검증으로 교체하고 새 운영 자격 증명을 부여해야 합니다.

## 저장 및 인증 범위

- 데이터는 같은 브라우저·같은 origin의 localStorage에 저장됩니다. 새로고침 후 유지되지만 다른 기기나 브라우저와 공유되지 않습니다.
- 실제 개인정보를 입력하지 마세요. localStorage는 인증이나 안전한 개인정보 저장소가 아닙니다.
- NPU는 로컬 승인코드, 관리자는 로컬 ID·비밀번호를 확인한 뒤 입장합니다. 클라이언트의 모의 인증은 운영용 접근 제어를 제공하지 않습니다.
- 프론트엔드에는 로컬 테스트 코드만 있으며 운영 승인코드, Google 인증정보, Sheets ID는 없습니다.
- 모의 API도 기업별 조회·상태 변경 범위를 검사하며, Web Locks 지원 브라우저에서는 같은 origin의 여러 탭 변경을 직렬화합니다. Web Locks 미지원 환경에서는 단일 탭 처리만 직렬화됩니다.
- 실제 다중 사용자 정원 보호는 GAS 서버에서 반드시 다시 구현해야 합니다. 운영 준비가 완료된 서비스가 아닙니다.

## 후속 연결 및 GitHub Pages

[Google Apps Script 연결 설계](docs/google-apps-script-integration.md)에 데이터 매핑, API 계약, 인증·원자적 정원 검증과 후속 확인 항목을 정리했습니다.

현재 파일은 GitHub Pages 루트 정적 배포 구조에 맞춰 작성되어 있습니다. 공개 저장소에 게시할 때는 데모 데이터 외의 개인정보·인증정보가 포함되지 않도록 하고, 저장소의 Pages 설정에서 배포 브랜치의 루트 폴더를 지정합니다. 배포 대상은 Chojungseok/2026-ITS-World-Congress-K-NPU-Business-Meeting- 저장소입니다. Settings > Pages에서 Deploy from a branch, main, /(root)를 선택하고 저장하면 됩니다. Pages 활성화 전에는 사이트 URL이 열리지 않습니다.


## 검증 결과

- Node 단위 테스트 27개 통과: 기업별 정원, 중복 신청, 소유 범위, 상태 전이, 취소 후 정원 반환, 손상 데이터, 입력 검증, 기업별 승인코드, 관리자 인증, 시간대별 정원 독립성·승인 경합, 로그 시간순 정렬, 이전 데이터 이관.
- Microsoft Edge 헤드리스: 신청 → 승인 → 신청 조회 → 취소, 거절, 정원 초과 승인 차단, 관리자 복합 필터 확인.
- 320 / 390 / 768 / 1024 / 1440px에서 네 화면의 페이지 가로 넘침 없음, 모바일 메뉴 동작 확인.
- 동일 브라우저 두 탭의 마지막 자리 동시 승인에서 한 건만 확정됨을 확인.
- 브라우저 오류 0건. 실제 GAS 서버 동시성·권한 검증은 아직 수행 대상이 아닙니다.

## ITS 신청 화면 변경

- 첫 화면 아래의 신청 현황 확인에서 신청ID만 입력하여 조회합니다.
- ITS 신청·조회 화면에서는 NPU 승인 관리와 운영 대시보드 메뉴를 숨깁니다. 이는 화면 구성으로, 운영용 인증을 대신하지 않습니다.
- 개인정보 수집 동의는 별도의 필수 체크박스로 받으며 오른쪽 화살표로 내용을 펼칩니다. 신규 신청에 동의 여부·시각·안내문 버전을 저장합니다.
- 개인정보 안내는 로컬 시연 기준입니다. 운영 보유기간은 확정 전이며, 현재 데이터는 데모 초기화 또는 브라우저 저장 데이터 삭제 시까지 보관됩니다.
- [개인정보 보호법 제15조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033214947)를 참고해 수집 목적·항목·보유기간·동의 거부 안내를 구분했습니다.
- 이전 시간표로 입력한 신청은 보존합니다. 기본 예시 13건만 새 시간표에 맞춰 표시합니다.
